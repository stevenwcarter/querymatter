# REPL UX Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Five REPL quality-of-life features — startup banner, one-history-entry-per-statement, a row-count line, a `.describe` dot-command, and tab-completion — all in `src/repl.rs` + small `src/session.rs` additions.

**Architecture:** `repl::run`'s read loop gains a banner, a history hook, and a stderr row-count line; a new `.describe` dot-command reads per-field stats from a new `Session::describe`; `DefaultEditor` is replaced by an `Editor<Helper,FileHistory>` with a custom completer. The one-shot/`-e`/batch surface and default rendered output are untouched.

**Tech Stack:** Rust edition 2024, `rustyline` 18 (Editor/Completer/Helper), existing `Session`/`RecordStore`/`Value`, `insta`, `assert_cmd`.

**Spec:** `docs/superpowers/specs/2026-07-24-repl-ux-design.md`

## Global Constraints

- Edition 2024; `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` clean, no `#[allow]`.
- **Default render output byte-identical:** `git diff main -- src/snapshots/` empty; the `tests/cli.rs` one-shot/`-e`/batch tests are unchanged (this batch does not touch that surface).
- Binary-only crate: `cargo test <filter>`, never `--lib`. No pre-commit hook — run `cargo fmt --all` and `cargo clippy --all-targets -- -D warnings` yourself before every commit.
- **stdout discipline:** in the REPL, query results and the startup banner go to stdout; the row-count line and `.describe`-error lines go to **stderr**. Batch/`-e` mode emits NO banner and NO row-count line.
- If you run the binary, set `HOME` and `XDG_CONFIG_HOME` to a fresh temp dir so you never touch the real `~/.config/querymatter/`.
- Existing seams: `repl.rs` — `PROMPT` (~25), `FILE_COLUMNS` (~31), `DotCommand` (~51), `LineBuffer` (~102), `parse_dot` (~173), `run` (~241), `DefaultEditor::new` (~242), `add_history_entry` (~268), `dispatch_dot` (~304), `print_help` (~393), `print_schema` (~419), `record_count` (~433), `history_path` (~492). `session.rs` — `render_statement` (~194), `schema()` (~255); the store is reachable for `records()`. `model.rs` — `Value::display()` (~30), `Record::field_names()` (~154). `config.rs` — `ConfigKey::ALL`.

### Task 1: Startup banner + one-entry-per-statement history (W4 + W5)

Both are small edits to `repl::run`'s loop; grouped because they touch the same lines.

**Files:** Modify `src/repl.rs`.

**Interfaces:**
- Consumes: `record_count(session)`, `LineBuffer`'s assembled `Statement`, `Line` enum.
- Produces: a testable `fn history_entry(line: &Line) -> Option<String>` (or equivalent) returning what to add to history for a resolved line.

- [ ] **Step 1: Write the failing test**

```rust
    #[test]
    fn history_records_one_entry_per_statement_not_per_line() {
        // Feed a multi-line statement through LineBuffer and assert the
        // history hook yields exactly one entry equal to the joined statement.
        let mut b = LineBuffer::new();
        assert_eq!(history_entry(&b.push("SELECT status")), None);      // More
        assert_eq!(history_entry(&b.push("FROM 'x'")), None);          // More
        let done = b.push("WHERE status = 'draft';");                  // Statement
        let entry = history_entry(&done).expect("a completed statement is recorded");
        assert!(entry.contains("SELECT status") && entry.contains("WHERE status = 'draft'"));
        // a dot-command records one entry; blank records none
        let mut b2 = LineBuffer::new();
        assert_eq!(history_entry(&b2.push("")), None);
        assert!(history_entry(&b2.push(".schema")).is_some());
    }
```

- [ ] **Step 2: Run to verify it fails**

Run: `cargo test repl::tests::history_records_one_entry`
Expected: FAIL — `history_entry` not found.

- [ ] **Step 3: Implement the history hook + banner**

Add `fn history_entry(line: &Line) -> Option<String>` returning: `Some(joined statement text)` for `Line::Statement` (reconstruct the runnable text — the `Statement.sql` plus its terminator, or just `sql`; pick one and be consistent), `Some(the dot line)` for `Line::Dot` (carry the original line text — if `DotCommand` doesn't retain it, thread the raw line), `None` for `Blank`/`More`. In `run`, REMOVE the unconditional `editor.add_history_entry(line.as_str())` at ~268 and instead, after `buffer.push(&line)` resolves, call `history_entry(&resolved)` and add it when `Some`.

Print the banner once before the loop:

```rust

        "querymatter — {} records. Type .help for commands, .schema for fields.",
        record_count(&session)
    );
```

- [ ] **Step 4: Run tests** — `cargo test repl::` passes; **Step 5:** fmt+clippy+snapshot-guard; **Step 6:** commit `feat(repl): startup banner and one-history-entry-per-statement`.

### Task 4: REPL tab-completion (W13)

**Files:** Modify `src/repl.rs`.

**Interfaces:**
- Produces: a custom rustyline helper type with a `Completer` impl; `Editor<Helper, FileHistory>` replacing `DefaultEditor`; a testable `fn complete_candidates(line: &str, pos: usize, schema: &[String], dot_names: &[&str]) -> Vec<String>`.

- [ ] **Step 1: Failing test**

```rust
    #[test]
    fn completion_candidates_by_position() {
        let schema = vec!["status".to_string(), "prd".to_string()];
        // dot-command completion after '.'
        let c = complete_candidates(".sc", 3, &schema, DOT_COMMAND_NAMES);
        assert!(c.iter().any(|x| x == ".schema"));
        // config-key completion after '.set '
        let c = complete_candidates(".set for", 8, &schema, DOT_COMMAND_NAMES);
        assert!(c.iter().any(|x| x == "format"));
        // column completion for a bare word in SQL position
        let c = complete_candidates("SELECT sta", 10, &schema, DOT_COMMAND_NAMES);
        assert!(c.iter().any(|x| x == "status"));
        // no SQL-keyword noise
        assert!(!c.iter().any(|x| x.eq_ignore_ascii_case("select")));
    }
```

- [ ] **Steps 2–4:** Define `DOT_COMMAND_NAMES: &[&str]` as the single source of the dot-command names (and have `parse_dot`/`print_help` reference it where practical so they can't drift). Implement `complete_candidates` (pure, testable): if the line's current word starts at `.` → dot-command names with that prefix; if the line starts with `.set `/`.unset ` and the cursor is on the value word → `ConfigKey::ALL` names with that prefix; else → `schema` fields + `FILE_COLUMNS` with that prefix. Implement a helper struct holding a schema snapshot (`session.schema()` at REPL start) that implements `rustyline::completion::Completer` (delegating to `complete_candidates`) plus no-op `Hinter`/`Highlighter`/`Validator`/`Helper` (use rustyline's derive where available, else hand-impl). Wire `Editor::with_config(...)`/`Editor::new()` + `editor.set_helper(Some(helper))` in place of `DefaultEditor`. The completer must never panic or block input.

- [ ] **Step 5:** commit `feat(repl): tab-completion for columns, dot-commands, and config keys`.
